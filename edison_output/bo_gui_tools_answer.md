## Software Tools Making Bayesian Optimization Accessible to Experimental Scientists (2020–2026): A Literature Review

### 1. Introduction

Bayesian optimization (BO) has emerged as a powerful framework for guiding experimental design in chemistry, materials science, and adjacent laboratory sciences. However, the complexity of existing BO libraries and the steep learning curve associated with them have deterred researchers who are not well-versed in machine learning or programming (baird2502honegumianinterface pages 1-3). To bridge this gap, a growing number of software tools have been developed that lower the barrier to entry through graphical user interfaces (GUIs), web applications, no-code/low-code platforms, interactive dashboards, and template generators. This review identifies and characterizes 19 such tools published between approximately 2020 and 2026.

### 3. Detailed Tool Descriptions

**Honegumi** is an interactive, web-based template generator that takes the form of a selection grid allowing users to configure key parameters of their optimization tasks, dynamically generating ready-to-use, unit-tested Python scripts built on top of the Ax Platform (baird2502honegumianinterface pages 1-3). It targets experimental researchers in materials science, chemistry, and biology who are not well-versed in machine learning. The tool supports 4,096 unique combinations of settings and is accompanied by a suite of conceptual and coding tutorials.

**Web-BO** is a browser-based GUI designed to support BO for chemical optimization tasks (mroz2025webbotowardsincreased pages 1-2). It links with the electronic lab notebook datalab and allows chemists to interact with BO algorithms without requiring advanced coding experience. The platform is explicitly designed to address the limited accessibility of BO algorithms in chemistry, where implementing BO is largely limited to interfacing via various APIs.

**BOXVIA** (Bayesian Optimization eXecutable and VIsualizable Application) is a desktop GUI application published in SoftwareX, targeting materials science and physics experimentalists (bousige2025optimeobayesianoptimization pages 2-4). It provides an executable with visualization capabilities for conducting BO campaigns without programming.

**EDBO** (Experimental Design via Bayesian Optimization) was introduced alongside a landmark study demonstrating that BO outperforms human decision-making in reaction optimization (shields2021bayesianreactionoptimization pages 1-2). It provides an open-source Python library that allows chemists to integrate state-of-the-art optimization algorithms into everyday laboratory practices. The framework was validated on palladium-catalyzed direct arylation, Mitsunobu, and deoxyfluorination reactions.

**EDBO+** extends EDBO to support multiobjective optimization, upgrading from Expected Improvement to q-Expected HyperVolume Improvement (q-EHVI) acquisition functions (shen2025bayesianoptimizationfor pages 10-11). It was applied to simultaneously optimize yield and enantioselectivity in nickel/photoredox-catalyzed enantioselective cross-electrophile coupling reactions, outperforming 500 manual experiments in just 24 experiments.

**AutoOED** (Automated Optimal Experiment Design Platform) provides a desktop GUI platform for automated multiobjective experimental design, available as both source code and executables (bousige2025optimeobayesianoptimization pages 1-2, bousige2025optimeobayesianoptimization pages 2-4). It is referenced as one of the key comparable tools alongside BOXVIA and MADGUI in the field.

**ProcessOptimizer** is an open-source Python package designed for easy Bayesian optimization of real-world processes, targeting experimentalist scientists (bertelsen2025processoptimizeranopensource pages 1-2, bertelsen2025processoptimizeranopensource pages 3-4, bertelsen2025processoptimizeranopensource pages 2-3, bertelsen2025processoptimizeranopensource pages 4-5). It provides a simplified ask/tell interface with comprehensive plotting features, benchmarking capabilities, noise management, multiobjective optimization, and batch-mode operation. Users interact through Python commands with minimal code, making it accessible to scientists with minimal Python training.

**NIMS-OS** (NIMS Orchestration System) is a Python library with a companion GUI application for controlling automated materials exploration systems (tamura2023nimsosanautomation pages 1-5). It implements a closed loop between AI algorithms (including PHYSBO for Bayesian optimization) and robotic experimental equipment, with visualization tools for real-time monitoring of optimization results.

**OPTIMEO** is a Streamlit-based web application requiring no knowledge of Python, published in the Journal of Open Source Software (bousige2025optimeobayesianoptimization pages 1-2). Users can generate a design of experiments, perform Bayesian optimization to find optimal parameters, or run machine learning regression models—all through a browser-based interface. It distinguishes itself from AutoOED, BOXVIA, and MADGUI by providing automatic setting of feature bounds and the ability to build initial experimental designs (bousige2025optimeobayesianoptimization pages 1-2).

**CIME4R** is an open-source interactive web application tailored to the analysis requirements of reaction optimization campaigns (humer2024cime4rexploringiterative pages 1-2). It supports users in comprehending reaction parameter spaces, investigating iterative RO processes, identifying critical reaction factors, and understanding AI model predictions. It was developed and evaluated in collaboration with domain experts at Bayer.

**NEXTorch** (Next EXperiment toolkit in PyTorch) extends BoTorch to democratize BO in chemical sciences, providing connections to real-world problems including automatic parameter scaling, data type conversions, GPU acceleration, and visualization (wang2021nextorchadesign pages 1-2). It supports both automated and human-in-the-loop optimization and includes comprehensive online documentation with examples from catalyst synthesis, reaction condition optimization, parameter estimation, and reactor geometry optimization.

**BoFire** (Bayesian Optimization Framework Intended for Real Experiments) is an open-source Python package developed by a consortium of major chemical companies (Evonik, BASF, Boehringer Ingelheim) that combines BO with classical design of experiments strategies (durholt2025bofirebayesianoptimization pages 1-3). It features JSON-serializability enabling seamless integration into RESTful APIs for both self-driving laboratories and human-in-the-loop setups, and includes cheminformatics capabilities such as molecular representations.

**BayBE** (Bayesian Back End) is an open-source framework developed by Merck KGaA for BO in real-world industrial contexts (fitzner2025baybeabayesian pages 1-2). Beyond core BO, it provides chemical and custom categorical encodings, transfer learning BO, and automatic stopping of unpromising campaigns. These features can reduce the average number of experiments by at least 50% compared to default implementations. BayBE has been adopted by multiple autonomous laboratory platforms.

**Olympus (enhanced)** provides a benchmarking framework with 23 experiment planning algorithms and 33 benchmark datasets from the chemistry and materials science literature (hickman2023olympusenhancedbenchmarking pages 1-2). The enhanced version includes a Streamlit web application for code-free usage, enabling researchers to rapidly benchmark different optimization strategies without programming.

**Bgolearn / BgoFace** is a comprehensive Bayesian optimization framework for materials discovery (cao2026bgolearnaunified pages 4-6). Bgolearn provides a Python API requiring 3–5 lines of code for common workflows, while BgoFace offers a graphical user interface that eliminates programming barriers and auto-generates equivalent Python code. The framework has accumulated over 110,000 downloads and is applied across metallic materials, functional materials, and autonomous laboratory platforms.

**BOA** (Bayesian Optimization for Anything) introduces a language-agnostic architecture using JSON serialization to facilitate communication between different programming languages (scyphers2024bayesianoptimizationfor pages 1-9). It is designed for users with limited expertise in BO, providing a high-level framework with command-line interface and model wrapper toolkit. It was demonstrated on environmental modeling applications.

**BORA** (Bayesian Optimization Research Assistant) couples a Large Language Model with standard BO in a hybrid optimization framework that automatically monitors and enriches searches with domain knowledge (cisse2025languagebasedbayesianoptimization pages 1-2). It was validated on real-world experimental tasks in chemical materials design, solar energy production, and crop production.

**IvoryOS** is an open-source web interface orchestrator that automatically generates web interfaces for Python-based self-driving laboratories (zhang2025ivoryosaninteroperable pages 1-2). It provides a drag-and-drop user interface for workflow design and no-code configuration for iterative execution, supporting both human-in-the-loop and closed-loop experimentation. It was integrated with six SDLs across two institutes.

**MADGUI** (Multi-Application Design Graphical User Interface) provides a desktop GUI for active learning assisted by Bayesian optimization, targeting materials scientists and experimentalists (bousige2025optimeobayesianoptimization pages 2-4).

### 5. Discussion

The landscape of accessible BO tools for experimental scientists spans a spectrum of interface paradigms. At one end, fully no-code web applications such as **OPTIMEO** (bousige2025optimeobayesianoptimization pages 1-2) and the Streamlit-enabled **Olympus** (hickman2023olympusenhancedbenchmarking pages 1-2) allow researchers to upload data and run BO campaigns entirely through browser interfaces. Desktop GUI tools such as **BOXVIA** (bousige2025optimeobayesianoptimization pages 2-4), **AutoOED** (bousige2025optimeobayesianoptimization pages 2-4), **MADGUI** (bousige2025optimeobayesianoptimization pages 2-4), **NIMS-OS** (tamura2023nimsosanautomation pages 1-5), and **BgoFace** (cao2026bgolearnaunified pages 4-6) provide native applications with point-and-click interaction. Web-based GUIs like **Web-BO** (mroz2025webbotowardsincreased pages 1-2) and interactive dashboards like **CIME4R** (humer2024cime4rexploringiterative pages 1-2) address the chemistry community specifically, with Web-BO providing integration with electronic lab notebooks.

At the other end, template and scaffold generators like **Honegumi** (baird2502honegumianinterface pages 1-3) take an educational approach, generating unit-tested scripts that researchers can modify, while low-code Python libraries such as **ProcessOptimizer** (bertelsen2025processoptimizeranopensource pages 1-2), **NEXTorch** (wang2021nextorchadesign pages 1-2), **BayBE** (fitzner2025baybeabayesian pages 1-2), **BoFire** (durholt2025bofirebayesianoptimization pages 1-3), and **EDBO** (shields2021bayesianreactionoptimization pages 1-2) minimize coding requirements through simplified APIs. Orchestration platforms such as **IvoryOS** (zhang2025ivoryosaninteroperable pages 1-2) bridge the gap between BO algorithms and laboratory hardware through drag-and-drop workflow design.

All tools identified are open source, reflecting the community's commitment to transparency and reproducibility. Most explicitly target wet-lab experimental optimization in chemistry and materials science, with exceptions like **BOA** (scyphers2024bayesianoptimizationfor pages 1-9), which targets environmental modeling, and **BORA** (cisse2025languagebasedbayesianoptimization pages 1-2), which uses LLM augmentation to inject domain knowledge into BO campaigns across diverse scientific domains. The publication venues span high-impact journals (*Nature*, *Nature Chemistry*, *Nature Communications*), domain-specific journals (*Digital Discovery*, *Faraday Discussions*, *J. Chem. Inf. Model.*), and software-focused outlets (*JOSS*, *SoftwareX*, *J. Cheminformatics*), indicating the maturation of this research area across the publication landscape.
